## 0. 요약 (먼저 읽을 것)

최초 문서는 "in-sample 연 44.7% / OOS 연 27.5% / 균등 연 32%, 과적합은 의심되나
균등 가중치면 robust"라고 결론지었다. **코드를 검증한 결과 이 숫자들은 전부 무효다.**

| 항목 | 최초 문서 | 검증 결과 |
|---|---|---|
| in-sample Sharpe 1.90 | 과적합 의심 | **재현 불가.** 같은 코드·데이터로 4회 실행 시 0.98~1.62로 흔들림 |
| OOS Sharpe 1.10 | "과적합 방어 신호" | 노이즈 밴드 안의 한 표본. SE가 ±0.72라 0과 구분 불가 |
| a_041 (가중치 17~20%) | "sqrt(고저) - VWAP 괴리" | **VWAP이 아니라 20일 평균 거래대금.** 사실상 "거래대금 최소" 팩터 |
| 균등 연 32% "robust" | 권장 | **전 종목을 그냥 보유하면 연 29.4%.** 전략은 그보다 못함 |
| 벤치마크 비교 | 없음 | 모든 기간에서 벤치마크 미달 |

**결론: 과적합 이전에 백테스트가 성립하지 않았다.** 버그 4개를 고치고 다시 측정한
결과, 이 알파 8개 조합에는 벤치마크를 넘는 신호가 없다. 가중치를 조정해서 해결되는
문제가 아니다.

## 1. 발견된 버그와 수정

수정 코드는 전부 `scratch/lib/alpha-engine.js`에 모았고, 기존 4개 스크립트는
이 엔진을 쓰도록 재작성했다.

### [1][2] 백테스트가 재현되지 않았음 — 가장 심각

같은 DB, 같은 코드, 같은 시드로 4번 실행한 결과:

| 실행 | 3년 균등 Sharpe | 3년 최적 Sharpe | OOS test Sharpe | 균등 baseline |
|---|---:|---:|---:|---:|
| 1회 | 1.07 | 1.79 | 1.28 | 34.1%/년 |
| 2회 | 1.35 | 1.72 | 0.98 | 34.5%/년 |
| 3회 | 1.26 | 2.00 | 1.50 | 32.4%/년 |
| 4회 | 1.62 | 2.23 | 1.54 | 41.0%/년 |
| **문서 기록** | **0.54** | **1.90** | **1.10** | **32.0%** |

원인 두 가지가 겹쳤다.

1. 알파 계산 쿼리에 `ORDER BY`가 없어 DuckDB 멀티스레드 실행마다 행 순서가 달라짐
2. `a_053`은 하루 평균 **6.9개**, `a_upday`는 **5.5개** 값만 갖는데 종목은 87개다.
   즉 평균 13~16종목이 완전 동점인데, 랭킹 코드가
   `ranks.get(r.code)[k] = i / (sorted.length - 1)`로 **DB 행 순서 그대로** 서로 다른
   랭크를 부여했다. Top 3만 담으므로 랭크가 한 칸 밀리면 종목이 통째로 바뀐다.

**수정**: 쿼리에 `ORDER BY code, date` 추가 + 동점을 **평균 순위**로 처리.
→ 수정 후 3회 실행 결과가 소수점까지 완전히 동일함을 확인했다.

### [3] a_041이 알파가 아니라 유동성 팩터였음

```sql
AVG(dp.volume * dp.close) OVER (...) AS vwap   -- 이건 VWAP이 아니라 20일 평균 거래대금
POWER(high * low, 0.5) - vwap AS a_041
```

```
avg(sqrt(high*low)) =        18,512 원
avg("vwap")         = 5,464,154,073 원      ← 약 30만 배
corr(a_041, -"vwap") = 0.9999999999999
```

가격 항이 완전히 묻혀 `a_041 ≡ -거래대금`이 됐다. 즉 "거래대금이 가장 적은 종목을 사라"는
신호이고, 슬리피지 0% 가정과 결합해 허수 수익을 만들었다 (단독 실행 시 test 구간 연 354%).

**수정**: DB에 이미 `trading_value` 컬럼이 있으므로 **실제 일별 VWAP =
`trading_value / volume`** 으로 교체하고, 가격 수준 차이를 없애기 위해 `close`로 나눠
무차원화했다.

### [4] 결측값을 0.5로 채워 매수 대상으로 만들었음

`a_003` 21.9%, `a_009` 25.1%가 NULL이다 (종목의 가격 순위가 10일간 변하지 않으면
상관계수가 정의되지 않음 — 가격 랭크는 매우 끈끈해서 자주 발생).

기존 코드는 이걸 `Number.isFinite(...) ? ... : 0.5`로 처리했는데, 상관계수 범위
[-1, 1]에서 **0.5는 상위권**이다. 즉 데이터가 없는 종목이 매수 후보가 됐다.

**수정**: 결측은 해당 알파 랭킹에서 제외하고, 남은 알파의 가중치를 재정규화.
확보된 가중치가 50% 미만인 종목은 그날 후보에서 제외.

### [5] 같은 날 종가 신호 → 같은 날 종가 매수

**수정**: 기본값을 `t일 종가 신호 → t+1일 시가 진입 → t+21일 시가 청산`으로 변경.
(참고로 이 항목의 영향은 작았다 — Sharpe 0.40 → 0.40)

### [6] 유동성 필터 없음

**수정**: 20일 평균 거래대금 하한(기본 5억) 추가. 이 유니버스는 거래대금 중앙값이
2.27억으로 생각보다 얕아서, 5억 하한을 걸면 87종목 중 평균 35종목만 남는다.

### [7] 벤치마크 비교가 아예 없었음 — 결론을 뒤집는 항목

**수정**: 유니버스 동일가중 보유 수익률을 같은 체결 기준으로 계산해 초과수익과
t값을 함께 리포트. 벤치마크는 회전율이 사실상 0이므로 비용을 물리지 않는다
(물리면 전략의 비용 부담이 상쇄돼 초과수익이 부풀려진다).

### [8] 가중치 탐색이 Dirichlet이 아니었음

`rng() + 0.1` 정규화는 개별 가중치를 **1.6~40.7%** 로 제한하고 대부분 12.5% 근처에
몰린다. 게다가 LCG 주기가 233,280으로 너무 짧았다.

**수정**: mulberry32 + Marsaglia-Tsang gamma 샘플러로 **진짜 Dirichlet(α=1)** 구현.

### [9] 다중비교 보정 없음

**수정**: Sharpe 표준오차, t값, **Deflated Sharpe Ratio**(Bailey & López de Prado) 추가.

### [G][H] IC 분석과 단일 알파 시뮬의 통계 오류

- IC를 전체 종목-일자 pooled Pearson으로 계산 → 종목별 스케일 차이가 지배.
  **일자별 cross-sectional Spearman rank IC**로 교체.
- "|IC| > 0.02 = 유의미 (p<0.05)" 근거 없음. 20일 forward return은 20일치가 겹쳐
  자기상관이 심하다. **Newey-West 보정 t값**으로 교체.
- `sim-top3-swing.js`가 매일 진입하면서 20일 보유로 계산 → 표본이 20배 중첩.
  **비중첩(리밸런싱 간격 = 보유기간)** 으로 교체.

## 2. 수정 후 결과

설정: Top 3, 20일 리밸런싱/보유, t+1 시가 체결, 비용 0.6% round trip, 유동성 하한 5억.

### 2.1. 기간별 — 균등 가중 전략 vs 벤치마크

| 기간 | 전략 net | 전략 gross | 벤치마크 | 초과(net) | 초과(gross) |
|---|---:|---:|---:|---:|---:|
| train 3y (21/08~24/08) | CAGR -8.5%, Sh -0.42 | CAGR -1.3% | CAGR -0.3%, Sh 0.05 | 연 -8.1%p (t=-1.05) | 연 -0.5%p (t=-0.07) |
| **test 2y (24/08~26/08)** | CAGR 6.1%, Sh 0.40 | CAGR 14.3% | **CAGR 29.4%, Sh 2.07** | 연 -19.2%p (t=-1.37) | 연 -11.6%p (t=-0.83) |
| 최근 3y (23/08~26/08) | CAGR 1.4%, Sh 0.16 | — | CAGR 11.9% | 연 -16.8%p (t=-1.69) | — |
| 전체 5y | CAGR -3.0%, Sh -0.08 | — | CAGR 2.5% | 연 -12.5%p (t=-1.73) | — |

**gross(비용 0)로도 초과수익이 음수다.** 즉 "신호는 있는데 비용이 먹는" 상황이 아니라
애초에 종목 선택이 가치를 더하지 못한다.

최초 문서의 "OOS 27.5%, 균등 32%"는 2024~2026 한국 시장 상승분(벤치마크 연 29.4%)의
일부를 받은 것이지 알파가 아니다.

### 2.2. 가중치 최적화는 OOS에서 살아남지 못함

Walk-forward (직전 구간 최적 가중치 → 다음 구간 실적), OOS 구간만 이어붙임:

| 전략 | n | CAGR | Sharpe | 벤치 대비 초과 |
|---|---:|---:|---:|---:|
| 최적A (Sharpe 목적) | 36 | 2.6% | 0.24 | 연 -15.7%p (t=-1.86) |
| 최적B (정보비율 목적) | 36 | -7.7% | -0.33 | 연 -25.9%p (t=-2.52, **유의하게 나쁨**) |
| 균등 | 36 | 1.4% | 0.16 | 연 -16.8%p (t=-1.69) |
| **벤치마크** | 36 | **20.6%** | **1.60** | — |

in-sample 최적화의 상방 편향 (5년 전체, Dirichlet 1000 trial):

```
균등 가중       : Sharpe -0.08
1000 trial 평균 : Sharpe -0.19 (SD 0.31)
1000 trial 최대 : Sharpe  0.72 = 평균 + 3.0σ   <-- 기존 "최적 가중치"
귀무가설 하 기대 최대 Sharpe : 1.00
Deflated Sharpe Ratio        : 26.3%  → 95% 미달, 탐색 운으로 설명 가능
```

즉 **순수 노이즈에서 1000번 뽑아도 Sharpe 1.00 정도는 나온다.** 실제로 찾은 0.72는
그보다도 낮다.

### 2.5. 부호를 맞추면 개선되지만 여전히 벤치마크 미달

train 구간에서만 부호를 추정해 test에 적용 (전체 구간으로 정하면 미래참조):

```
부호 정렬 전 균등W : CAGR  6.1%, Sharpe 0.40, 초과 연 -19.2%p
부호 정렬 후 균등W : CAGR 25.3%, Sharpe 0.96, 초과 연  -0.7%p (t=-0.04)
벤치마크           : CAGR 29.4%, Sharpe 2.07
```

크게 개선되지만 여전히 벤치마크를 못 넘고, MDD는 -15.1% vs 벤치 -8.4%로 더 나쁘다.
게다가 train에서 정한 부호 중 a_041은 test에서 뒤집혔다 (8개 중 7개만 유지).

## 3. 최초 문서 Q1~Q5에 대한 답

**Q1. 과적합 여부 / 다중비교 보정**
과적합이 맞지만 그보다 재현성이 먼저 문제였다. 보정 결과 DSR 26.3%로 95% 미달이며,
귀무가설 하 기대 최대 Sharpe(1.00)가 실제 탐색 최대(0.72)보다 높다. BH FDR을 적용할
단계 이전에서 막힌다. Sharpe SE는 37매매 0.58, 24매매 0.72다.

**Q2. 가중치 안정성 / 베이지안 shrinkage**
기간별 변동폭이 평균 16.0%p로 균등 가중치보다 크다. shrinkage로 안정화해도 수렴 대상이
균등 가중치이므로 의미가 없다. 지금 필요한 건 shrinkage가 아니라 **알파 부호 정렬과
팩터 선별**이다.

**Q3. 실전 권장 가중치**
권장할 가중치가 없다. 이 8개 조합으로는 어떤 가중치도 벤치마크를 넘지 못했다.
현 시점의 합리적 선택은 **유니버스 동일가중 보유**다.

**Q4. 알파 추가/개선**
101개를 더 넣기 전에 지금 8개의 부호부터 맞춰야 한다. cross-correlation은 실측 결과
문제가 아니었다(최대 0.55). 랜덤 포레스트 같은 비선형 결합은 24~37 표본에서
과적합만 심해진다.

**Q5. 시뮬레이션 정확도**
슬리피지 0% 가정이 a_041 버그와 결합해 허수를 만들었다. 유동성 필터 민감도는 매우 크다
(하한 0억 → 초과 +11.2%p, 5억 → -11.6%p, 30억 → +0.8%p). 이 정도 흔들린다는 것 자체가
결과가 노이즈 지배라는 신호다.

## 4. 남은 한계 (코드로 못 고침)

1. **생존편향** — DB에 상장폐지 종목이 없다. 5년 데이터가 있는 87종목은 전부 생존 종목이다.
   기존 `HAVING COUNT(*) >= 1000` 필터도 미래참조지만, 애초에 DB에 폐지 종목 자체가 없어
   코드로는 교정 불가. 실제 성과는 여기 숫자보다 낮다.
2. **표본 부족** — 비중첩 매매가 5년에 61회뿐. 어떤 결론도 통계적 검정력이 약하다.
3. **MDD 과소평가** — 20일 비중첩 수익률 기준이라 실제 일중 낙폭보다 작게 나온다.
4. **유니버스 87종목** — KOSPI 200 전체가 아니며 거래대금 중앙값 2.27억으로 얕다.

  - `scratch/test-alphas-batch.js` — 일자별 rank IC + NW t값 + 알파 간 상관
